# TMBA v0.8.2 – pi-gen Stage Chaining

## Ziel

Behebung des Buildabbruchs beim Eintritt in die eigene `stage-tmba`.

## Ursache

`pi-gen` erzeugt für jede Stage ein eigenes Arbeitsverzeichnis. Eine neue benutzerdefinierte Stage muss das Root-Dateisystem der vorherigen Stage ausdrücklich mit `copy_previous` übernehmen. In v0.8.1 fehlte dazu die Datei `stage-tmba/prerun.sh`. Deshalb existierte `stage-tmba/rootfs` beim ersten chroot-basierten Paketschritt noch nicht.

## Änderung

- `image-builder/pi-gen-stage/prerun.sh` ergänzt
- Root-Dateisystem aus `stage2` wird vor allen TMBA-Schritten kopiert
- Builder-Validierung prüft das Vorhandensein und die Syntax des Prerun-Skripts
- automatischer Test stellt die Verwendung von `copy_previous` sicher
- Release- und Image-Version auf `0.8.2` aktualisiert

## Erwartetes Ergebnis

Der Build kann nach `stage2` in `stage-tmba/00-tmba-packages` wechseln und Pakete im übernommenen Bookworm-Root-Dateisystem installieren.
