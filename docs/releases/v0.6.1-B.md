# TMBA-OS v0.6.1-B

## Ziel

Integration der logischen AudioPipeline in den bestehenden AudioManager.

## Geändert

- AudioManager erzeugt standardmäßig eine AudioPipeline.
- Eine Pipeline kann für Tests injiziert werden.
- Erfolgreiches `play` startet die Pipeline.
- `stop` stoppt Quelle und Pipeline.
- Quellenwechsel stoppen die Pipeline.
- Pipeline-Startfehler führen zu einem Rollback der Quelle.
- Pipelinefehler werden über den bestehenden AudioManager-Fehlerweg behandelt.
- `get_pipeline_status()` stellt den Status intern bereit.

## Hinzugefügt

- neun Integrationstests
- ADR-0003
- Prüfskript für Teilmeilenstein B

## Bewusst nicht enthalten

- kein neuer REST-Endpunkt
- kein Frontend
- kein ALSAOutputDriver
- kein CamillaDSP
- keine reale Audioverarbeitung

## Hinweis zur Dienstregistrierung

`register_default_sources()` bleibt in diesem Paket noch am Ende von
`manager.py`, weil für eine sichere Verlagerung der aktuelle Stand von
`backend/tmba/main.py` benötigt wird. Diese rein strukturelle Änderung wird
getrennt vorgenommen und nicht mit der Pipeline-Integration vermischt.
